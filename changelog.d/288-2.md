- **Session logs: a terminal's output saved to a file while the session runs.** Off unless you turn it on, in Settings › Terminal: "Text only" (what you'd read on the screen) or "All output" (everything, escape codes too), a folder (empty is "Submarine logs" in your Documents), and a file name with PuTTY's codes such as `&S &Y-&M-&D &T.log`. A server's form can choose for that server, on this device only. It works for SSH, container and telnet terminals, not Home's local shells, and not on phones. The terminal says where it's logging, or why it can't. (Their [#403](https://github.com/SinaXhpm/submarine/pull/403); [#288](https://github.com/paulm981/Submarine/issues/288))
  - **A log holds whatever the screen showed.** That includes a password a prompt echoed, anything a server printed (a `cat .env`), and a secret Library command's text once the shell echoes it. A password typed at a prompt that doesn't echo (sudo, ssh, the root password) isn't in it.
  - On Linux and macOS, only you can read a log: it's made readable by you alone, and so are the folders made for it. A folder or log that was already there keeps its own permissions.
  - A log stops at 1 GB, with a line in the file and in the terminal saying so. The terminal goes on; only the log stops.
  - A name that would leave the log folder isn't used, and on Windows neither is a name Windows keeps for a device, such as `NUL` or `CON`. The terminal says why.
  - A slow folder never slows the terminal: what the log can't keep up with is left out, and the log says how much.
