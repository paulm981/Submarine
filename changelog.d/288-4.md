- **Servers that ask for a one-time code after the password now log in.** A server that takes a password and then a code (Google Authenticator through PAM, say) used to fail as if the password were wrong. Now the password you saved or typed answers the server's password question, so it isn't asked twice, and then the code is asked. A wrong password is asked for again with "The password was rejected", up to three times. Jump hosts do the same. (Their [#417](https://github.com/SinaXhpm/submarine/pull/417); [#288](https://github.com/paulm981/Submarine/issues/288))
  - **Save password** still saves only the first password a server asks for. When you're asked again after a wrong one, the tick is there again. A server that asks for a second, different password after the first gets no tick for it, so it never replaces a saved login other servers share.
  - A connection that can't ask you anything (a tab's SFTP or port forwarding connection, a terminal's own login) still stops at the code. Monitoring still can't watch a server that asks for a code.
  - On a server that takes both kinds of login without a code, a wrong saved password is now tried twice before you're asked for it.
